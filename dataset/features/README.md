# 特集の作業の手引き

ポケふた図鑑（https://data.pokefuta.com/ ）の特集ページを直すための手引きです。
はじめて担当する人は、上から順に読んでください。

## 1. 特集ページのしくみ

特集ページ `https://data.pokefuta.com/features/<slug>/` は、このフォルダの2つのファイルからできています。
`<slug>` は特集ごとの名前です（例: `okinawa-2026-autumn`）。

| ファイル | 中身 |
|---|---|
| `<slug>.json` | タイトル・公開日・載せる蓋の ID・お披露目と設置の日程・関連リンク |
| `<slug>.html` | **本文**（読み物の部分）と**ニュース欄**。HTML で書く |

蓋の一覧・地図・パンくず・検索エンジン向けのデータは、プログラムが JSON から作ります。
`.html` に書くのは本文とニュースだけです。`.html` が無い特集は、本文もニュースも JSON に書いてあります。

担当の特集:

| 特集 | ページ | ファイル |
|---|---|---|
| 沖縄にポケふたが4枚増えます | https://data.pokefuta.com/features/okinawa-2026-autumn/ | `okinawa-2026-autumn.html`（本文・ニュース） |
| 高知のポケふた第4弾 | https://data.pokefuta.com/features/kochi-2026-autumn/ | `kochi-2026-autumn.html`（本文） |
| 群馬県に初めてのポケふた | https://data.pokefuta.com/features/gunma-2026-autumn/ | `gunma-2026-autumn.html`（本文） |

## 2. 作業の流れ

このリポジトリはチームで開発しています。`main` ブランチは直接書き換えられず、
**変更はすべて Pull Request（PR）を通し、レビューを受けてから本番に出ます。**

1. **Issue を読む** — やることは Issue に書いてあります（[good first issue の一覧](https://github.com/nishiokya/pokefuta-tracker/issues?q=is%3Aopen+label%3A%22good+first+issue%22)）。
   始めるときは Issue に「やります」とコメントする
2. **フォークを最新にする** — 自分のフォークのページで「Sync fork」→「Update branch」
3. **ブランチを作る** — フォークのページ左上のブランチ名 → 新しい名前を入れて「Create branch」。
   名前は内容が分かるものにする（例: `kochi-list`）。**1つの Issue に1つのブランチ**
4. **編集する** — 作ったブランチを開いた状態で「.」キーを押すと、ブラウザで VS Code（github.dev）が開く。
   `dataset/features/` のファイルを直す
5. **コミットする** — 左の「ソース管理」で、何を変えたかを1行で書いて「Commit & Push」
   （例: `高知の設置場所を箇条書きにする`）
6. **PR を出す** — フォークのページに出る「Compare & pull request」から。説明に次を書く
   - 何を変えたか、なぜか
   - `Closes #<Issue の番号>`（マージされると Issue が自動で閉じる）
7. **検査を待つ** — PR の下の「Checks」で **Check Features** が緑になるのを確かめる。
   はじめての PR は、レビューする人が許可するまで検査が始まりません
8. **レビューを受ける** — Copilot（AI）とレビューする人がコメントします。直したら同じブランチにコミットすれば PR に足されます。
   分からないコメントは、そのまま返信して聞いてよい
9. **マージ → 本番で確かめる** — マージはレビューする人がします。数分でデプロイが終わるので、
   本番のページで変わったことを確かめて、PR に「確認しました」とコメントする

## 3. 本文の書き方

```html
<!-- メモはこう書く。ページには出ない -->
<section>
  <h2>見出し</h2>
  <p>段落。<strong>強調</strong>や<a href="/prefectures/gunma/">図鑑の中へのリンク</a>も書ける。</p>
  <ul>
    <li>箇条書き</li>
  </ul>
</section>

<section>
  <h2>次の見出し</h2>
  <p>……</p>
</section>
```

- `<html>` `<head>` `<body>` は書かない。本文の部分だけを書く
- 一番外側には `<section>` を並べる。`<section>` は必ず `<h2>` の見出しから始める
- 文字は `<p>` `<li>` `<td>` などの中に書く（`<section>` や `<ul>` に直接書かない）
- `<` `>` `&` を文字として書きたいときは `&lt;` `&gt;` `&amp;`

使えるタグ: `section` `h2` `h3` `p` `ul` `ol` `li` `a` `strong` `em` `br` `table` `thead` `tbody` `tr` `th` `td`

## 4. ニュース欄の書き方

ニュース欄は、`.html` の中の `<section id="news">` に書きます（ページでは蓋の一覧と地図の下、いちばん最後に出ます）。

```html
<section id="news">
  <h2>公式発表・ニュース</h2>
  <ul>
    <li>
      <a href="https://local.pokemon.jp/municipality/okinawa/">沖縄×ガーディ｜ポケモンローカルActs</a>
      <small>ポケモン公式</small>
    </li>
    <li>
      <a href="https://www.okinawatimes.co.jp/articles/-/1946198">記事の見出しをそのまま</a>
      <small>沖縄タイムス・<time datetime="2026-10-16">2026年10月16日</time></small>
    </li>
  </ul>
</section>
```

- 記事1本が `<li>` 1つ。`<a>` に**記事の見出し**、`<small>` に**媒体名**を書く
- 日付が分かるときは `媒体名・<time datetime="2026-10-16">2026年10月16日</time>`。
  `datetime` と表示の日付は同じ日にする（違うと検査で止まる）。分からなければ `<time>` ごと書かない
- 見出しは `<h2>公式発表・ニュース</h2>` のまま変えない
- ニュースの節で使えるのは `section` `h2` `ul` `li` `a` `small` `time` だけ

### 記事を選ぶときのルール

- リンクは **`https://` で始まるものだけ**
- 並べる順は **公式（ポケモン・県・市町村）が先**、そのあとに新聞社・テレビ局・ゲーム媒体（4Gamer・ファミ通など）
- **Yahoo!ニュースや NHK の記事は数か月で消えます。** 同じ記事が新聞社・テレビ局のサイトにあれば、そちらにリンクする
- 見出しは記事のものをそのまま写す。記事の本文はコピーしない
- 記事を開いて、その特集の話題（どの県の何回目のポケふたか）と合っているかを必ず確かめる

## 5. 使えるタグを絞っている理由

ここに無いタグ・属性（`<script>` `<img>` `<iframe>` `<div>` `<b>` `style=` `onclick=` など）が1つでもあると、
**その特集はページに出なくなり**、検査も赤くなります。

このサイトはログインを扱っているので、ページに好きな HTML を入れられると、
ログイン中の人の情報を盗むスクリプトを仕込めてしまいます（XSS）。
そこで「危ないものを探して断る」のではなく、**「安全だと分かっているものだけ通す」**作りにしています（許可リスト方式）。
`id` や `class`、別タブで開く設定（`target="_blank"`）は、プログラムが付けます。

## 6. 検査が赤くなったら

PR の「Checks」→ Check Features → 「Check feature files」を開くと、だめなところがこう出ます。

```
  NG gunma-2026-autumn.html 3行目: <b> は使えない
```

| 出てくる言葉 | 直し方 |
|---|---|
| `<b> は使えない` | 使えるタグに直す（太字は `<strong>`） |
| `〇〇 属性は使えない` | `style` や `class` を消す |
| `の閉じ方が合わない` | 開いたタグと閉じるタグの順番を見る（`<p><strong>…</p></strong>` は ✕） |
| `最後まで閉じていないタグがある` | `</p>` や `</section>` の書き忘れ |
| `https:// か / で始める` | リンク先を直す。ニュースの記事は `https://` だけ |
| `datetime と合わない` | `<time datetime="…">` と表示の日付をそろえる |
| `JSON にも news がある` | ニュースは `.html` か `.json` のどちらか一方だけに書く |
| JSON が読めない・書式が違う | `,` の付け忘れ・付けすぎ、`"` の閉じ忘れを見る |

手元に Python があれば、同じ確認をこれで回せます: `python3 apps/scraper/features.py`

## 7. 守ること

- **このリポジトリは誰でも見られます。** コミット・PR・Issue に、本名・学校名・住所・ほかの利用者の名前を書かない
- 1つの PR では1つのことだけをする（箇条書きに直す PR で、文章まで直さない）
- 事実（場所・日付・枚数）を変えるときは、出典の URL を PR に書く
- 分からないこと・迷うことは、Issue か PR にコメントして聞く。黙って進めない
